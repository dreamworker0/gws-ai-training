업무용 앱, 어떤 도구로 만들까?
ChatGPT Sites 장단점과 다른 도구 비교

ChatGPT Sites, Claude 아티팩트, Firebase, 구글 앱스 스크립트, Vercel, Supabase를 같은 기준으로 놓고 봤습니다. 개인 계정과 기관(업무) 계정에서 무엇이 달라지는지, 우리 기관에서 자주 만드는 앱 유형별로 어떤 도구가 맞는지도 함께 정리했습니다.

한눈에 결론 용어 풀이 여섯 가지 도구 비교표 ChatGPT Sites 장단점 개인 vs 업무 계정 상황별 추천 퇴사 대비 퇴사자 처리(관리자) 아직 모르는 것 출처

한눈에 결론

  • 기관 안에서만 쓰는 간단한 관리 도구(비품 대장, 회의실 예약, 업무 현황판)는 ChatGPT Sites나 Claude 아티팩트로 빠르게 만들 수 있습니다. 둘 다 말로 설명하면 AI가 화면과 저장 기능까지 만들어 줍니다.
  • 정해진 시간에 메일을 보내거나 매달 자동으로 집계하는 일은 ChatGPT Sites와 Claude 아티팩트 모두 못 합니다. 구글 앱스 스크립트(소규모)나 기존 Cloud Run(대규모)이 맞습니다.
  • 이용자 상담 기록·사례 관리처럼 민감한 개인정보는 ChatGPT Sites와 Claude 아티팩트에 넣지 않는 쪽을 권합니다. 데이터가 어느 나라에 저장될지 고를 수 없기 때문입니다. 꼭 직접 만들어야 한다면 서울 리전을 고를 수 있는 Firebase나 Cloud Run을, 개인정보 담당자 검토를 거쳐 쓰는 편이 낫습니다.
  • Vercel + Supabase는 Firebase와 비슷한 "개발자용" 선택지입니다. 서울 리전을 고를 수 있고 자유도가 높지만, 코드를 직접 관리해야 하고 기관 업무용이면 유료 플랜이 필요합니다(Vercel 무료 플랜은 개인·비상업용, Supabase 무료 프로젝트는 일주일 쓰지 않으면 일시정지).
  • 어떤 도구든 반드시 기관 계정으로 만드세요. 개인 계정으로 만든 앱은 그 사람이 계정을 지우거나 퇴사하면 함께 사라지거나 멈출 수 있습니다.

먼저, 용어 풀이

서버리스
서버 컴퓨터를 직접 관리하지 않고, 요청이 올 때만 잠깐 코드가 실행되는 방식. 편하지만 오래 걸리는 작업이나 예약 작업은 제약이 많습니다.
D1 / R2
ChatGPT Sites가 쓰는 Cloudflare의 저장소. D1은 표 형태 데이터베이스(엑셀 시트와 비슷), R2는 파일 보관함입니다.
예약 작업(트리거)
"매일 아침 9시에 메일 발송"처럼 사람이 누르지 않아도 정해진 때에 저절로 돌아가는 기능.
데이터 저장 지역(리전)
데이터가 실제로 보관되는 나라·데이터센터. 개인정보 보호 측면에서 국내(서울) 보관 여부가 중요할 수 있습니다.
워크스페이스(기관 계정)
ChatGPT Business/Enterprise, Claude Team/Enterprise, Google Workspace처럼 기관이 관리하는 계정 묶음. 관리자가 사용자와 데이터를 관리할 수 있습니다.
Postgres(포스트그레스)
Supabase가 쓰는 데이터베이스 종류. 업계 표준이라 나중에 다른 곳으로 옮기기 쉽습니다.
시크릿
외부 서비스와 연결할 때 쓰는 비밀 키. 비밀번호와 같으니 화면이나 코드에 그대로 적으면 안 됩니다.

여섯 가지 도구, 한 줄 소개

ChatGPT Sites

OpenAI · 구 Codex Sites

ChatGPT에 말로 설명하면 웹앱을 만들어 인터넷 주소로 올려 줍니다. 데이터베이스와 파일 저장소가 함께 붙어 나옵니다.

Claude 아티팩트

Anthropic

Claude와 대화하며 만든 웹페이지를 claude.ai에 올려 공유합니다. 기관 플랜에서는 공유 데이터 저장, 파일 업로드, 보는 사람 확인, Claude에게 질문하기 같은 기능을 페이지에 붙일 수 있습니다.

Firebase

Google · 개발자용 플랫폼

웹앱용 데이터베이스·로그인·파일 저장·호스팅을 묶은 서비스. 코드를 직접(또는 AI 도움으로) 짜야 하지만 가장 자유롭습니다.

구글 앱스 스크립트

Google · 시트·메일 자동화

구글 시트·지메일·캘린더·드라이브를 자동으로 움직이는 스크립트. 예약 발송이나 시트 집계에 특히 강하고, 간단한 웹 화면도 만들 수 있습니다.

Vercel

웹사이트 배포 서비스

직접 짠 웹앱 코드를 올리면 주소를 붙여 배포해 줍니다. 화면과 간단한 서버 코드는 맡지만 데이터베이스는 따로 붙여야 합니다.

Supabase

데이터베이스·로그인 서비스

Postgres 데이터베이스, 로그인, 파일 저장을 한꺼번에 제공합니다. Vercel과 짝을 지어 "화면은 Vercel, 데이터는 Supabase"로 많이 씁니다.

ChatGPT Sites 장단점 자세히

장점

  • 만들기가 가장 쉽습니다. 화면, 데이터베이스, 파일 저장, 로그인까지 한 번에 붙어 나옵니다.
  • 허락받은 사람만 쓰게 할 수 있습니다. 새 사이트는 소유자와 관리자만 볼 수 있고, "초대한 사람만"으로 두면 초대한 직원·그룹·외부인만 들어옵니다. 필요하면 기관 전체나 인터넷 전체로 넓힐 수도 있어 외부 신청 페이지도 가능합니다.
  • 로그인이 편합니다. 내부용은 기관 ChatGPT 계정으로, 외부용은 ChatGPT 로그인이나 외부 로그인 서비스로 붙일 수 있습니다.
  • 저장 공간이 넉넉합니다. 데이터베이스 사이트당 10GB, 파일 보관함은 고정 한도가 없습니다.
  • 올해 말까지 호스팅 무료라 시험 삼아 써 보기 좋습니다.

단점·주의할 점

  • 예약·자동 작업이 안 됩니다. 매일 알림 메일, 야간 집계 같은 기능은 다른 도구가 필요합니다.
  • 데이터 저장 지역을 고를 수 없습니다. 이용자 민감정보는 넣지 않는 편이 안전합니다.
  • 테스트 환경이 따로 없습니다. 고치는 순간 바로 실제 사용자에게 반영됩니다.
  • 지우면 복구가 안 됩니다. CSV 내보내기 버튼을 만들어 두고 정기적으로 백업해야 합니다.
  • 2027년부터 비용이 생길 수 있고, 플랜별 허용량은 아직 공개되지 않았습니다(사이트별 사용량 보고는 2026-12-01부터).
  • 퇴사 시 처리가 애매합니다. 소유권 이전은 되지만, 퇴사자 계정을 지울 때 사이트가 자동으로 넘어가는지는 공식 문서에 없습니다.
  • 권한 정리를 꼼꼼히 해야 합니다. 한 사람의 초대를 지워도 그룹·워크스페이스 전체·공개 설정으로 계속 들어올 수 있습니다.
  • 외부 데이터베이스, 일반 서버 프로그램(Node.js), 오래 걸리는 작업은 지원하지 않습니다.

허락받은 사람만 쓰게 하는 방법

  1. 사이트에서 Share를 누르고 Who has access를 "Only those invited(초대한 사람만)"로 둡니다.
  2. 이메일이나 그룹을 검색해 Viewer 권한으로 Invite를 누릅니다.
  3. 링크를 보내면서 "초대받은 그 계정으로 로그인하세요"라고 안내합니다. 다른 계정으로 로그인하면 들어오지 못합니다.

기관 밖 사람을 초대할 때

  • 외부 초대는 Plus·Pro·Business·Enterprise 플랜에 차례로 열리는 중입니다. 메뉴가 안 보이면 아직 열리지 않았을 수 있습니다.
  • Enterprise는 관리자가 Workspace settings > Permissions & roles에서 "Allow members to invite external visitors to sites"를 켜야 합니다. Business는 이 스위치가 따로 없습니다.
  • 외부 초대와 인터넷 공개는 서로 다른 설정입니다. 외부 초대를 허용해도 사이트가 인터넷에 공개되지는 않습니다. Enterprise는 공개 게시가 기본으로 꺼져 있습니다.
  • 초대받은 외부인은 보기만 할 수 있습니다. 수정·게시는 못 하고 워크스페이스 멤버가 되지도 않습니다. 로그인하려면 ChatGPT 계정이 필요할 것으로 보입니다(공식 문서에 명시되지 않음).

참고: Cloudflare를 직접 쓰면?

ChatGPT Sites는 Cloudflare의 Workers(서버리스 실행), D1(데이터베이스), R2(파일 보관함) 위에서 돌아갑니다. Cloudflare를 직접 쓰는 것은 같은 엔진을 ChatGPT 없이 쓰는 셈입니다. 그래서 Sites에서 "안 된다"고 한 것 중 상당수는 Cloudflare가 아니라 Sites의 제약입니다.

직접 쓰면 생기는 것

  • 예약 작업: Cron Triggers로 정해진 시간에 실행(무료 계정당 5개, 유료 250개)
  • 작업 대기열(Queues)과 테스트용 환경 분리
  • 직원 전용 로그인 보호: Cloudflare Access, 50명까지 무료
  • 파일 전송비 없음: R2는 내려받기 전송 요금이 없고 10GB까지 무료

잃거나 그대로인 것

  • 말로 만드는 편리함: 코드와 배포를 직접 관리해야 합니다.
  • 무료 플랜은 빡빡함: 하루 10만 요청, 요청 1건당 CPU 시간 10ms. 조금만 무거워도 유료(Workers Paid)가 필요합니다.
  • 저장 지역은 여전히 대략적: D1은 "아시아·태평양" 같은 권역 힌트만 줄 수 있고 보장되지 않습니다. 엄격한 지정은 EU·미국 등만 되고 한국은 없습니다.

언제 고려할까: Sites로 만든 앱이 커져서 예약 작업이 필요해지거나, 직접 운영으로 옮기고 싶을 때. D1·R2 구조가 같아서 옮기기가 비교적 쉽습니다. 다만 개발 부담은 Vercel + Supabase나 Firebase와 비슷하니, 이미 Cloud Run을 쓰는 우리 기관에서는 우선순위가 높지 않습니다.

퇴사·인수인계 대비 체크리스트 (만든 사람용)

  1. 기관 계정으로 만들기. 개인 Gmail, 개인 ChatGPT·Claude 계정으로 업무 앱을 만들지 않습니다.
  2. 소유자는 팀장이나 관리자 계정이 갖기. 사이트마다 편집자를 2명 이상 둡니다.
  3. 퇴사 전에 소유권 이전. ChatGPT Sites는 같은 워크스페이스의 활동 중인 멤버에게 넘길 수 있습니다. 앱스 스크립트는 공유 드라이브로 옮기고 예약 작업을 공용 계정으로 다시 만듭니다.
  4. 데이터 백업. CSV로 내려받아 기관 공유 드라이브에 보관합니다.
  5. 시크릿(비밀 키) 인계. 소유권을 넘긴 뒤에도 유지되는지 확인되지 않았으니, 키 값과 발급처를 따로 안전하게 넘깁니다.
  6. 이미 퇴사 처리됐다면 워크스페이스 관리자가 사이트를 찾아 소유권을 이전합니다. 보이지 않으면 OpenAI 지원팀에 문의합니다.

퇴사자가 생겼을 때 관리자가 할 일

위 체크리스트는 앱을 만든 직원이 미리 챙길 일이고, 여기는 기관 관리자(팀장·전산 담당)가 할 일입니다. 핵심은 "계정을 지우기 전에 옮기고, 지운 뒤에 확인한다"입니다.

공통 순서

  1. 퇴사 통보를 받으면앱 대장 확인. 퇴사자가 만들었거나 소유자로 있는 앱·사이트·스크립트·프로젝트를 모두 적습니다. 평소에 "앱 이름 · 도구 · 소유자 · 편집자 · 쓰는 시크릿" 대장을 두면 이 단계가 5분이면 끝납니다.
  2. 마지막 출근일 전소유권 이전과 백업. 각 앱의 소유권을 남는 직원(가능하면 팀장·관리자 계정)에게 넘기고, 데이터를 CSV 등으로 내려받아 기관 공유 드라이브에 보관합니다.
  3. 마지막 출근일 전예약 작업 옮기기. 퇴사자 계정으로 돌던 예약 발송·집계를 공용(기능) 계정이나 남는 직원 계정으로 다시 만듭니다.
  4. 퇴사일계정 정리. 바로 삭제하지 말고, 구글은 먼저 정지, ChatGPT·Claude는 멤버에서 제거합니다. 로그인 연동(SCIM)을 쓰면 연동 쪽 그룹에서도 빼야 다시 추가되지 않습니다.
  5. 퇴사일비밀 키 다시 발급. 퇴사자가 알던 시크릿·API 키·DB 비밀번호·액세스 토큰을 새로 만들어 앱에 넣고, 옛 키는 폐기합니다.
  6. 퇴사일공유 정리. 퇴사자가 초대한 외부인, 퇴사자 개인에게 걸린 권한을 정리합니다. 한 사람을 지워도 그룹·전체 공유로 접근이 남을 수 있으니 공유 범위를 함께 봅니다.
  7. 1~2주 뒤동작 확인 후 삭제. 예약 메일이 제대로 나갔는지, 사이트가 열리는지 확인한 다음 계정을 삭제합니다. 처리 내용을 기록으로 남깁니다.

  • 퇴사자가 만든 Codex 액세스 토큰 폐기, 연결된 드라이브·슬랙 등 점검
  • 프로젝트·GPT는 워크스페이스 소유자에게 자동 이전되지만 Sites는 문서에 없음 → 제거 후 사이트가 보이지 않으면 OpenAI 지원팀 문의
Claude 아티팩트
  • 퇴사자의 아티팩트를 동료 계정으로 다시 게시하거나, 편집 권한을 동료에게 공유
  • 공유 저장소 데이터를 내려받아 보관
  • 퇴사자의 비공개 프로젝트에 있는 자료를 조직 공유 프로젝트로 옮기기
  • 조직 Owner만 멤버를 제거할 수 있음
  • 제거하면 그 사람의 채팅·비공개 프로젝트는 다른 멤버가 볼 수 없음. 조직 전체에 공유한 프로젝트는 남음
  • Primary Owner는 제거된 멤버의 채팅·프로젝트를 내보낼 수 있음(보관 기간 설정 영향)
  • 아티팩트가 어떻게 되는지는 문서에 없음 → 반드시 제거 전에 옮기기. Enterprise는 감사 기록으로 남은 아티팩트 확인
Firebase
  • Google Cloud 권한(IAM)에서 남는 직원에게 소유자 역할 부여
  • 결제 계정 관리자 변경
  • 개인 계정 프로젝트라면 기관 조직으로 이전
  • IAM에서 퇴사자 역할 제거
  • 퇴사자가 만든 API 키·서비스 계정 키 재발급
  • 기관 조직 아래 프로젝트는 계정을 지워도 관리자가 계속 관리 가능
앱스 스크립트
  • 스크립트와 연결된 시트를 공유 드라이브로 옮기기
  • 예약 트리거를 공용 계정으로 다시 만들기(트리거는 만든 사람 계정으로 실행됨)
  • "나로 실행" 웹앱은 새 소유자 계정으로 다시 배포하고 주소가 바뀌면 안내
  • 메일 발신자가 바뀐다는 점을 이용자에게 알리기
  • 관리 콘솔에서 먼저 정지(정지 중에도 요금은 청구됨)
  • 삭제할 때 드라이브 데이터 이전을 선택해 남는 직원에게 넘기기
  • 삭제 후 20일 안에는 계정 복구 가능
Vercel
  • 팀 소유자 역할을 남는 직원에게 이전
  • 퇴사자 개인 GitHub로 연결된 저장소는 기관 GitHub 조직으로 옮기기(안 하면 자동 배포가 끊김)
  • 개인 계정 프로젝트는 기관 팀으로 이전
  • Team Settings > Members에서 제거
  • 환경 변수의 비밀 키와 액세스 토큰 재발급
Supabase
  • 조직의 Owner 역할을 남는 직원에게 넘기기
  • 퇴사자 개인 조직에 있는 프로젝트는 기관 조직으로 이전
  • 조직 Team 설정에서 퇴사자 제거
  • DB 비밀번호와 비밀 키(service_role 등) 재발급. 바꾼 키를 앱 설정에도 반영
이미 계정이 지워졌다면: 구글 계정은 삭제 후 20일 안에 복구할 수 있습니다. ChatGPT는 관리자가 사이트 목록을 확인하고 보이지 않으면 OpenAI 지원팀에 문의하세요. Claude는 Primary Owner가 제거된 멤버의 데이터를 내보낼 수 있는지 먼저 확인하세요. 어느 경우든 시간이 지날수록 되살리기 어려우니 바로 움직이는 게 좋습니다.

아직 확인되지 않은 것

  • ChatGPT Sites: 초대받은 외부인에게 ChatGPT 계정이 꼭 필요한지(공식 문서는 "초대받은 계정으로 로그인"이라고만 안내)
  • ChatGPT Sites: 소유권 이전 메뉴의 정확한 위치와 절차, 소유자 계정을 지웠을 때 자동 이전 여부, 플랜별 호스팅 허용량, 업로드 1건 최대 크기, 이전 후 시크릿 유지 여부
  • Claude 아티팩트: 작성자가 퇴사했을 때 소유권 이전 방법, 데이터 저장 지역
  • 앱스 스크립트: 소유권을 넘겼을 때 기존 예약 작업과 웹앱 배포가 그대로 유지되는지(테스트 프로젝트로 직접 확인 권장)
  • Vercel 무료 플랜의 "비상업" 범위에 비영리 기관 업무가 들어가는지는 약관 해석이 필요합니다. 기관 업무라면 처음부터 Pro로 시작하는 편이 안전합니다.
  • Supabase 무료 플랜 파일 저장 용량은 자료마다 수치가 달라 공식 요금 페이지 확인이 필요합니다.
  • Claude 아티팩트의 기능은 베타 단계라 자주 바뀝니다. 도입 전에 기관 관리자 화면에서 다시 확인하세요.
