# 드림워크 교육 아카이브 디자인 계획서

> 작성일: 2026-09-20  
> 대상 사이트: <https://dreamworker0.github.io/gws-ai-training/>  
> 상태: 디자인 승인 완료, 구현 전

## 1. 목적

기존의 「구글 워크스페이스와 AI 교육 — 수강생 학습 페이지」를 **드림워크 교육 아카이브**로 재구성한다.

새 사이트는 두 방문자를 동시에 지원한다.

1. 교육을 이미 들은 수강생은 배운 주제, 발표자료, 영상, 공식 문서를 다시 찾는다.
2. 교육을 검토하는 기관 담당자는 드림워크의 교육 철학, 전문 분야, 진행 방식을 살펴본다.

기존 복습 기능을 잃지 않으면서 첫 화면에서 드림워크의 정체성과 교육 전문성이 드러나는 것이 성공 기준이다.

## 2. 브랜드 원칙

- 화면의 주 브랜드는 **드림워크**로 통일한다.
- 사이트명은 **드림워크 교육 아카이브**로 한다.
- `김종원`은 주 브랜드로 반복하지 않고, 소개와 하단 정보에서만 **교육자 김종원 · 소셜프리즘**으로 표기한다.
- 대표 문구는 **“도구보다, 일하는 방식의 변화”**로 한다.
- 특정 기관명, 기관별 진도, 진단 결과, 참석자 정보 등 공개하면 안 되는 정보는 넣지 않는다.
- 제품 로고를 장식으로 남용하지 않고 드림워크 고유의 인상을 우선한다.

## 3. 정보 구조

### 3.1 전역 내비게이션

- 드림워크
- 교육 분야
- 학습 아카이브
- 발표자료
- 드림워크의 관점
- 문의
- 검색
- 밝게/어둡게 전환

모바일에서는 핵심 진입점인 `수강생 복습`과 `교육 살펴보기`를 먼저 보여 주고, 나머지 메뉴는 간결한 메뉴 안에 둔다.

### 3.2 홈 화면

홈은 다음 순서로 구성한다.

1. **히어로**
   - 드림워크 교육 아카이브
   - “도구보다, 일하는 방식의 변화”
   - 사회복지 현장의 스마트워크와 AI 교육을 기록하고 나눈다는 설명
   - `수강생 복습하기`, `교육 살펴보기` 두 개의 행동 버튼
   - 대표 에디토리얼 일러스트
2. **방문 목적별 안내**
   - 수강생: 배운 주제, 슬라이드, 영상, 공식 문서를 다시 찾는 경로
   - 기관 담당자: 교육 분야, 진행 방식, 교육자 소개를 보는 경로
3. **대표 교육 분야**
   - Google Workspace
   - 데이터와 업무 자동화
   - 생성형 AI와 에이전트
4. **교육 아카이브 소개**
   - 현재 26개 교육 주제와 11개 발표자료 묶음을 유지한다.
   - 첫 화면에서는 트랙보다 전문 분야를 먼저 보여 복잡도를 낮춘다.
5. **드림워크의 관점**
   - 기존 강의 인용문을 에디토리얼 인용문으로 재구성한다.
6. **문의**
   - `복습 질문`과 `교육 문의`를 명확히 분리한다.

### 3.3 수강생 복습 화면

- 기존 `먼저 보기`, A트랙, B트랙 구조를 유지한다.
- 강의 정리, 슬라이드, 영상, 공식 문서, 관련 주제 추천을 유지한다.
- 기존 검색, 관계도, 전체 발표자료 보기, 전체 화면 슬라이드 뷰어를 유지한다.
- 홈의 `수강생 복습하기` 버튼은 이 화면의 시작점으로 이동한다.

### 3.4 교육 살펴보기 화면

- 드림워크가 다루는 세 교육 분야를 설명한다.
- 대상, 교육에서 얻는 변화, 진행 원칙을 짧게 제시한다.
- 교육자 정보는 `교육자 김종원 · 소셜프리즘`으로 한 번만 명확히 표시한다.
- 과장된 실적 숫자나 확인되지 않은 홍보 문구는 사용하지 않는다.
- 기관별 세부 일정이나 비공개 진단 정보는 표시하지 않는다.

### 3.5 주제 상세와 자료 화면

- 기존 해시 주소를 가능한 한 유지해 기존 링크가 깨지지 않게 한다.
- 주제 상세의 정보 순서는 `개요 → 발표자료 → 강의 내용 → 강사 설명 → 영상 → 공식 문서 → 관련 주제 → 질문`으로 유지한다.
- 콘텐츠가 없는 구역은 빈 카드로 남기지 않고 자연스러운 준비 중 문구를 제공한다.

## 4. 시각 디자인

### 4.1 방향

선택된 방향은 **따뜻한 에디토리얼 아카이브**다. 일반적인 온라인 강의 플랫폼보다 오래 보관하고 다시 펼쳐 보는 교육 잡지에 가깝게 만든다.

### 4.2 색상

- 주 색상: 짙은 포레스트 그린
- 강조색: 따뜻한 테라코타 오렌지
- 기본 배경: 종이 느낌의 부드러운 아이보리
- 본문: 녹색 기가 있는 짙은 먹색
- 보조 배경: 옅은 세이지 그린
- 다크 모드: 짙은 녹색 바탕, 낮은 채도의 오렌지, 따뜻한 회백색 본문

색상은 기능과 강조에만 사용한다. 카드마다 다른 색을 장식적으로 적용하지 않는다.

### 4.3 서체와 위계

- 큰 제목과 인용문: 차분한 한국어 명조 계열
- 본문, 버튼, 검색, 자료 목록: 화면 가독성이 좋은 한국어 고딕 계열
- 서체를 불러오지 못해도 시스템 글꼴로 읽기 좋게 유지한다.
- 본문은 모바일에서도 지나치게 작아지지 않게 한다.

### 4.4 형태와 여백

- 그림자보다 넓은 여백과 가는 경계선을 사용한다.
- 모서리는 지나치게 둥글지 않게 절제한다.
- 원과 연결선을 드림워크의 시각 모티프로 사용한다.
- 같은 모양의 카드가 끝없이 반복되지 않도록 인용문, 목록, 자료 표지의 리듬을 다르게 한다.

## 5. 대표 이미지

### 5.1 콘셉트

히어로에는 사진이 아닌 **추상적인 에디토리얼 일러스트**를 사용한다.

표현할 내용:

- 서로 연결되는 종이와 작업 화면의 형태
- 사람과 업무의 연결을 나타내는 노드와 선
- 작은 새싹 또는 성장하는 형태
- 기록이 쌓이고 다시 활용되는 흐름

이미지는 “특정 도구를 배우는 교육”보다 “사람과 일이 연결되며 변화하는 과정”을 전달해야 한다.

### 5.2 제작 규칙

- 용도: 데스크톱 히어로 오른쪽, 모바일에서는 제목 아래
- 구도: 가로형, 왼쪽 문구와 경쟁하지 않도록 오른쪽에 시각적 무게 배치
- 색상: 포레스트 그린, 테라코타, 아이보리, 세이지
- 스타일: 질감이 약간 있는 현대적 에디토리얼 콜라주
- 금지: 제품 로고, 사람 얼굴 클로즈업, 읽어야 하는 글자, 워터마크, 과도한 3D 광택
- 접근성: 내용 전달에 필수적인 글자를 이미지 안에 넣지 않고 적절한 대체 문구를 제공한다.
- 저장 위치: `img/dreamwork-archive-hero.*`

최종 이미지는 이미지 생성 도구로 만든 뒤 실제 히어로 레이아웃에서 잘림과 대비를 확인한다.

## 6. 구성 요소

### 6.1 히어로

- 브랜드명, 대표 문구, 설명, 두 행동 버튼, 대표 이미지로 구성한다.
- 두 행동 버튼의 우선순위는 동일하되 `수강생 복습하기`를 첫 번째로 둔다.

### 6.2 목적 선택 블록

- 수강생과 기관 담당자의 다음 행동을 각각 2~3개로 명확히 보여 준다.
- 역할을 선택했다고 해서 별도 계정이나 개인화 기능을 만들지는 않는다.

### 6.3 교육 분야 카드

- 제목, 한 문장 설명, 연결되는 대표 주제를 보여 준다.
- 카드 전체를 링크로 만들고 키보드 포커스를 명확히 표시한다.

### 6.4 아카이브 목록

- 기존 트랙과 항목 데이터를 그대로 활용한다.
- 자료 수, 영상 수, 강의 정리 여부를 짧은 메타 정보로 표시한다.
- 장식용 배지보다 제목과 설명을 우선한다.

### 6.5 인용문

- 한 번에 너무 많은 문장을 같은 크기로 나열하지 않는다.
- 대표 인용문 하나를 크게 보여 주고 나머지는 보조 목록으로 배치한다.

### 6.6 문의

- 수강생의 복습 질문과 기관의 교육 문의를 분리한다.
- 기존 이메일 주소 분할 방식과 메일 작성 동작을 유지한다.

## 7. 코드 구조와 데이터 흐름

현재의 빌드 과정 없는 정적 사이트를 유지한다.

- `index.html`: 홈과 하위 화면의 의미 구조, 접근성 있는 내비게이션
- `style.css`: 디자인 토큰, 레이아웃, 반응형 규칙, 다크 모드, 인쇄 스타일
- `data.js`: 브랜드 소개, 교육 분야, 인용문, 커리큘럼, 발표자료, FAQ
- `app.js`: 화면 렌더링, 해시 경로, 검색, 자료 뷰어, 테마
- `find.js`: 검색과 관련 주제 계산을 유지
- `img/`: 생성한 대표 이미지와 기존 발표자료 이미지

홈과 상세 화면은 같은 데이터 원본을 사용한다. 교육 분야의 대표 항목을 별도 복사하지 않고 기존 커리큘럼 ID를 참조해 중복과 불일치를 줄인다.

## 8. 오류와 빈 상태

- 대표 이미지가 로드되지 않아도 제목과 두 행동 버튼은 그대로 보인다.
- 유튜브 썸네일이 실패해도 영상 제목과 링크는 남는다.
- 슬라이드 이미지가 없으면 깨진 이미지 대신 자료 준비 중 상태를 표시한다.
- 검색 결과가 없으면 검색어를 포함한 간결한 안내를 보여 준다.
- 잘못된 해시 주소는 오류 화면 대신 홈으로 돌아가되 사용자가 길을 잃지 않게 안내한다.
- 자바스크립트를 사용할 수 없는 환경에서도 사이트의 목적과 기본 이동 경로는 HTML에서 읽을 수 있게 한다.

## 9. 반응형과 접근성

- 기준 폭: 360px 모바일부터 넓은 데스크톱까지
- 모바일에서 히어로는 문구, 행동 버튼, 이미지 순서로 세로 배치한다.
- 모든 주요 기능은 키보드로 접근할 수 있어야 한다.
- 포커스 표시를 제거하지 않는다.
- 텍스트와 배경의 명암 대비를 확인한다.
- 장식 이미지는 빈 대체 문구, 의미 있는 이미지는 설명형 대체 문구를 사용한다.
- `prefers-reduced-motion` 환경에서는 장식 애니메이션을 줄이거나 제거한다.
- 다크 모드에서도 영상 썸네일, 슬라이드, 입력창의 경계가 구분되어야 한다.

## 10. 구현 범위

이번 개편에 포함한다.

- 드림워크 중심의 브랜드와 문구
- 새 홈 정보 구조
- 교육 살펴보기 화면
- 기존 수강생 복습 기능의 새 디자인 적용
- 대표 이미지 생성과 적용
- 반응형·다크 모드·접근성 보완
- 기존 해시 링크와 검색 기능의 회귀 검증

이번 개편에 포함하지 않는다.

- 로그인과 회원 계정
- 서버 데이터베이스
- 기관별 비공개 페이지
- 결제·예약 기능
- 기기 간 진도 동기화
- 질문 게시판과 댓글

## 11. 검증

구현 후 다음을 확인한다.

1. `node scripts/check.mjs`로 기존 외부 링크를 점검한다.
2. 자바스크립트 구문 오류와 브라우저 콘솔 오류를 확인한다.
3. 홈, 각 트랙, 대표 주제 상세, 발표자료, 관계도, 검색의 해시 경로를 확인한다.
4. `수강생 복습하기`와 `교육 살펴보기` 동선을 각각 끝까지 확인한다.
5. 밝은 화면과 어두운 화면을 확인한다.
6. 360px 모바일, 태블릿, 데스크톱에서 잘림과 겹침을 확인한다.
7. 키보드만으로 메뉴, 검색, 카드, 자료 뷰어를 사용할 수 있는지 확인한다.
8. 대표 이미지와 유튜브 썸네일이 실패한 상태를 확인한다.
9. 기존 공개 URL의 주요 북마크가 계속 작동하는지 확인한다.

## 12. 배포 원칙

- 구현과 로컬 검증이 끝나기 전에는 공개 배포하지 않는다.
- 실제 공개 배포는 변경 내용과 검증 결과를 사용자가 확인한 뒤 진행한다.
- GitHub Pages 배포 후 공개 URL에서 캐시가 갱신되었는지 다시 확인한다.
