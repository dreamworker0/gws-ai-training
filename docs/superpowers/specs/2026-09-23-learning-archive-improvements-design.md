# 학습 아카이브 개선 설계

작성일: 2026-09-23  
대상: `smartwork/site` 정적 웹사이트  
상태: 구현 전 검토본

## 1. 목표

드림워크 교육 아카이브를 모바일에서도 빠르게 탐색할 수 있게 만들고, 새 발표자료를 해당 학습 주제에 연결하며, 검색·슬라이드 뷰어의 접근성과 회귀 테스트를 현재 정보구조에 맞춘다.

완료 조건은 다음과 같다.

- A04 구글 캘린더, A06 구글 킵·내 지도, A12 Slack 발표자료가 사이트에서 주제별로 열린다.
- 390px 모바일에서 상단 고정 영역이 화면을 과도하게 차지하지 않는다.
- 모바일 학습 목록은 분야별로 접고 펼칠 수 있으며, 링크 없이도 분야 제목을 이해할 수 있다.
- 검색 결과는 경로가 바뀌면 닫히고 키보드와 스크린리더로 탐색할 수 있다.
- 슬라이드 전체화면은 접근성 있는 모달로 동작하며 닫은 뒤 원래 버튼으로 포커스가 돌아간다.
- 잘못된 해시 주소와 JavaScript 비활성화 상태에서 사용자가 다음 행동을 알 수 있다.
- 현재 `GROUPS` 기반 정보구조를 검사하는 자동 테스트가 모두 통과한다.
- 기존 해시 주소, 다크 모드, 개인정보 보호 규칙, GitHub Pages 정적 배포 방식을 유지한다.

## 2. 범위

### 포함

1. 새 PDF 3종의 웹용 이미지·썸네일·캡션 생성
2. `DECKS`, `ITEM_SLIDES`, `SLIDE_TITLES` 갱신
3. 모바일 헤더와 분야별 학습 목록 개선
4. 검색 자동완성 접근성과 상태 정리
5. 슬라이드 전체화면 모달 접근성
6. 잘못된 주소 안내 및 실제로 유용한 `noscript` 대체 콘텐츠
7. 디자인 계약·경로·개인정보·외부 링크 테스트 갱신
8. 데스크톱, 390px 모바일, 밝은 화면, 어두운 화면의 브라우저 검증

### 제외

- 로그인, 진도 저장, 서버 데이터베이스
- 사이트 게시판이나 문의 폼
- 발표자료 자체 내용 수정
- 공개 배포와 GitHub 원격 저장소 푸시
- 나머지 25개 주제의 새 발표자료 제작

## 3. 설계 원칙

- 빌드 과정이 없는 HTML·CSS·JavaScript 정적 사이트 구조를 유지한다.
- 기존 데이터 원본인 `data.js`를 계속 사용한다.
- 새 프레임워크나 런타임 의존성을 추가하지 않는다.
- 모바일에서는 핵심 행동과 검색에 접근할 수 있으면서도 상단 고정 영역을 한 줄 수준으로 줄인다.
- 데스크톱 레이아웃은 현재의 에디토리얼 디자인을 최대한 유지한다.
- 보이는 버튼·목록의 상태와 접근성 속성이 항상 일치해야 한다.
- 기능 변경은 실패하는 자동 테스트를 먼저 추가한 뒤 구현한다.

## 4. 발표자료 연동

### 4.1 소스와 덱 ID

다음 PDF를 웹 자산으로 변환한다.

| 덱 ID | PDF | 페이지 | 연결 주제 |
|---|---|---:|---|
| `calendar` | `발표자료폴더/_재작업/A04_구글캘린더_v2.pdf` | 9 | `a04` |
| `keep` | `발표자료폴더/_재작업/A06_구글킵_구글지도_v2.pdf` | 8 | `a06` 1~4쪽, `a06-map` 5~8쪽 |
| `chat` | `발표자료폴더/_재작업/A12_구글챗_슬랙_v2.pdf` | 7 | `a12` |

`bin/slides-to-site.py`의 덱 정의는 파일명만 받지 않고 소스 폴더 기준 상대 경로도 받을 수 있게 한다. 기존 6개 덱의 출력은 바꾸지 않는다. 새 자산은 `img/slides/<덱 ID>/` 아래에 저장한다.

### 4.2 웹 표시

- 세 덱을 `data.js`의 `DECKS`에 추가한다.
- 각 주제의 `ITEM_SLIDES`에 위 표의 페이지를 모두 연결한다.
- 캡션에서 추출한 제목을 검토해 `SLIDE_TITLES`에 사람이 읽기 좋은 제목을 넣는다.
- 홈의 발표자료 수와 전체 페이지 수는 현재 계산 방식을 통해 자동 갱신한다.
- 자료가 없는 주제에는 기존처럼 빈 발표자료 제목을 만들지 않는다. 대신 학습 목록의 상태 배지만으로 자료 유무를 알 수 있게 한다.

## 5. 모바일 헤더와 학습 목록

### 5.1 헤더

640px 이하에서는 다음 구조를 사용한다.

- 첫 줄: 브랜드 링크, 검색 열기 버튼, 메뉴 열기 버튼, 테마 버튼
- 검색창과 내비게이션은 기본적으로 접힌 상태
- 검색 또는 메뉴 버튼을 누르면 헤더 아래에 해당 패널 하나만 펼쳐진다.
- 다른 패널을 열면 기존 패널은 닫힌다.
- Escape를 누르거나 패널 밖 링크로 이동하면 패널이 닫힌다.
- 버튼은 `aria-expanded`와 `aria-controls`로 상태를 노출한다.
- 데스크톱에서는 현재 검색창과 내비게이션을 그대로 표시한다.

### 5.2 학습 분야

- 640px 이하에서 각 `.group`은 접을 수 있는 분야가 된다.
- 첫 분야인 `구글 워크스페이스 시작하기`는 기본으로 열린다.
- 나머지 분야는 기본으로 닫아 긴 초기 스크롤을 줄인다.
- 분야 제목은 실제 `<button>`으로 렌더링하고 `aria-expanded` 및 `aria-controls`를 제공한다.
- 데스크톱에서는 7개 분야를 지금처럼 모두 펼쳐 보여 준다.
- JavaScript가 실행되지 않아도 정적 대체 링크를 통해 주요 학습 분야와 발표자료 화면으로 이동할 수 있다.

## 6. 검색

검색 입력은 접근성 있는 자동완성으로 동작한다.

- 입력에 `role="combobox"`, `aria-autocomplete="list"`, `aria-expanded`, `aria-controls`를 설정한다.
- 결과 컨테이너는 `role="listbox"`, 결과 링크는 `role="option"`을 사용한다.
- 결과 개수와 결과 없음 상태는 별도 `aria-live="polite"` 영역에서 알린다.
- 아래·위 화살표로 결과를 이동하고 Enter로 선택하며 Escape로 닫는다.
- 활성 결과는 `aria-activedescendant`로 입력과 연결한다.
- 해시 경로 변경, 결과 선택, 외부 클릭 시 결과창과 검색어를 정리한다.
- 검색어가 비어 있으면 결과창은 항상 닫힌다.

검색 알고리즘과 결과 순위는 이번 범위에서 변경하지 않는다.

## 7. 슬라이드 전체화면

전체화면 컨테이너에 `role="dialog"`, `aria-modal="true"`, 접근 가능한 이름을 추가한다.

- 열기 직전의 요소를 저장한다.
- 열리면 닫기 버튼으로 포커스를 이동한다.
- Tab과 Shift+Tab이 이전·다음·닫기 버튼 안에서 순환한다.
- Escape, 배경 클릭, 전체화면 종료로 닫을 수 있다.
- 닫을 때 전체화면을 종료하고 열기 직전 요소로 포커스를 복구한다.
- 화살표 키와 Space로 페이지를 넘기는 기존 동작을 유지한다.
- 슬라이드가 바뀌면 현재 페이지 수를 `aria-live="polite"`로 알린다.

## 8. 경로 오류와 JavaScript 대체 콘텐츠

### 8.1 잘못된 해시

알 수 없는 해시는 홈으로 조용히 보내지 않는다. 홈 레이아웃 안에 다음 내용을 표시한다.

- `요청한 자료를 찾지 못했습니다`
- 사용자가 입력한 해시를 화면에 다시 출력하지 않는다.
- `학습 아카이브 보기`와 `첫 화면으로` 링크 제공
- 문서 제목을 오류 상태에 맞게 갱신

### 8.2 JavaScript 비활성화

`noscript`에는 실제로 사용할 수 있는 정적 링크를 둔다.

- 첫 화면 소개
- 학습 아카이브 위치
- 발표자료 위치
- 문의 이메일 링크

JavaScript가 없으면 동적으로 생성되는 30개 주제 목록을 볼 수 없다는 점을 정확히 알린다.

## 9. 브랜드 표시

현재의 공개 URL과 검색 결과 연속성을 위해 HTML `<title>`과 `META.title`은 `GWS & AI 교육 아카이브`를 유지한다. 화면의 주 브랜드는 설계 문서에 맞게 다음처럼 정리한다.

- 헤더 브랜드: `드림워크 교육 아카이브`
- 보조 문구: `Google Workspace와 AI 교육 기록`
- 히어로 눈썹 문구: `드림워크 교육 아카이브`
- 푸터: `드림워크 교육 아카이브 · 교육자 김종원 · 소셜프리즘`

이 변경은 SEO 제목이나 기존 해시 주소를 바꾸지 않는다.

## 10. 테스트

### 10.1 데이터·자산 계약

`design-contract.test.mjs`는 더 이상 존재하지 않는 `track` 필드나 고정된 과거 캐시 문자열을 검사하지 않는다. 대신 다음을 검사한다.

- `GROUPS`의 모든 ID가 유일하고 모든 주제가 정확히 한 분야에 포함됨
- `CURRICULUM`의 모든 주제 ID가 유일함
- 새 덱 3종의 페이지 수와 연결 주제가 정확함
- `ITEM_SLIDES`의 모든 참조가 실제 덱 페이지 범위 안에 있음
- HTML의 CSS·JS 캐시 버전이 네 자산에서 동일함
- 모바일 토글, 검색 자동완성, 오류 안내, 뷰어 모달에 필요한 DOM과 접근성 속성이 존재함
- 기존 디자인 토큰, 대표 이미지, Open Graph 메타데이터 유지

### 10.2 동작 테스트

가능한 동작은 브라우저 독립적인 작은 함수로 분리해 Node 테스트에서 검증한다.

- 검색의 다음·이전 활성 결과 계산
- 경로 변경 시 검색 상태 초기화
- 모바일 분야의 기본 열린 상태
- 존재하지 않는 해시가 오류 화면을 선택함
- 뷰어 포커스 대상 목록과 복귀 대상 보존

기존 `routes.test.mjs`와 `privacy.test.mjs`는 계속 통과해야 한다. `scripts/check.mjs`로 외부 링크도 다시 확인한다.

### 10.3 브라우저 검증

- 데스크톱 기본 화면과 다크 모드
- 390×844 모바일 홈, 검색, 분야 펼치기, 주제 상세
- 검색 결과 키보드 선택과 경로 이동 후 닫힘
- A04·A06·A12 발표자료 열기와 전체화면 앞뒤 이동
- 잘못된 해시 안내
- 콘솔 오류와 경고 없음

## 11. 변경 파일

- `../../bin/slides-to-site.py`: `_재작업` PDF를 포함하는 변환 입력 지원
- `img/slides/calendar/**`: A04 웹 이미지
- `img/slides/keep/**`: A06 웹 이미지
- `img/slides/chat/**`: A12 웹 이미지
- `data.js`: 덱, 슬라이드 연결, 제목, 브랜드 표시 데이터

- `app.js`: 모바일 패널, 분야 접기, 검색 키보드 처리, 오류 경로, 뷰어 포커스 관리
- `style.css`: 모바일 헤더·분야·오류·접근성 상태 스타일

- `scripts/ui-behavior.test.mjs`: 브라우저 독립 상태 계산 테스트
- `README.md`: 새 덱 추가 방식과 검증 명령 갱신

## 12. 위험과 대응

- **기존 북마크 손상:** 기존 해시 정규식과 주제 ID를 그대로 유지하고 경로 테스트로 고정한다.
- **모바일 헤더가 다시 커짐:** 390px 브라우저 화면에서 닫힘·열림 상태를 각각 확인한다.
- **새 자산으로 저장소 증가:** 기존 JPEG 크기·품질 규칙을 재사용하고 큰 이미지와 썸네일을 분리한다.
- **검색 키보드와 마우스 상태 불일치:** 활성 결과를 단일 인덱스로 관리하고 DOM 속성은 그 상태에서만 갱신한다.
- **모달 포커스 유실:** 열기 직전 요소를 저장하고 DOM에 남아 있을 때만 복구한다.
- **테스트가 구현 세부사항만 검사:** 데이터 무결성과 사용자에게 보이는 동작을 우선 검사한다.
